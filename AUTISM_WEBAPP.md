# AUTISM_WEBAPP.md

This document explains how to run the simple web application that collects the autism screening questions and calls the fine-tuned Mistral model from this repository.

The code is split into:
- `frontend/` – static HTML page with the 10 screening questions and demographics.
- `backend/` – FastAPI server that loads the fine-tuned LoRA adapter and exposes an HTTP API.

## Prerequisites

- Python 3.10+ (use the same virtual environment you used for `llm_train.ipynb` if possible).
- The trained LoRA adapter directory `autism_screening_mistral_final/` present at the repo root.
- The same core ML dependencies used in the notebook (already installed if you ran training):
  - `transformers`
  - `peft`
  - `accelerate`
  - `bitsandbytes`
  - `torch`

Additional packages for the web API:

```bash
pip install fastapi "uvicorn[standard]"
```

> Note: The backend expects a GPU-capable environment with `bitsandbytes` working, similar to the fine-tuning notebook. It loads `mistralai/Mistral-7B-Instruct-v0.1` in 4-bit with LoRA.

## Backend: start the API server

From the repository root (`autism-llm-support`):

```bash
# Activate your venv first (example, adjust as needed)
# Windows PowerShell
#   .\venv\Scripts\Activate.ps1

cd backend
uvicorn main:app --reload --host 127.0.0.1 --port 8000
```

This will:
- Load the base Mistral model `mistralai/Mistral-7B-Instruct-v0.1` with 4-bit quantization.
- Attach the LoRA adapter from `autism_screening_mistral_final/`.
- Expose an HTTP API on `http://127.0.0.1:8000` with:
  - `GET /health` – simple health probe.
  - `POST /predict` – runs the model and returns a YES/NO/UNKNOWN prediction.

You can quickly check health with:

```bash
curl http://127.0.0.1:8000/health
```

You should see:

```json
{"status": "ok"}
```

### /predict request/response shape

- **Method**: `POST`
- **URL**: `http://127.0.0.1:8000/predict`
- **Body (JSON)**:

```json
{
  "A1": 1,
  "A2": 1,
  "A3": 0,
  "A4": 1,
  "A5": 0,
  "A6": 0,
  "A7": 1,
  "A8": 1,
  "A9": 0,
  "A10": 0,
  "Age": 15,
  "Sex": "m",
  "Jaundice": "no",
  "Family_ASD": "no"
}
```

- **Response (JSON)**:

```json
{
  "prediction": "NO",
  "raw_output": "NO",
  "prompt": "Patient screening info... (full text used for the model)"
}
```

The backend reconstructs the prompt in the same format as used in `llm_train.ipynb` (with
`### Instruction` / `### Response` sections) before calling the model.

## Frontend: open the questionnaire page

The frontend is a static HTML file in `frontend/index.html`. It uses JavaScript `fetch` to call the backend at `http://127.0.0.1:8000/predict` and displays the result.

### Option 1: open directly from the file system (quickest)

1. Start the backend as described above.
2. In your file explorer, open `frontend/index.html` with your browser (double-click).
3. Fill out all Yes/No questions and demographic fields.
4. Click **"Submit and Predict"**.
5. The page will show:
   - `Model prediction: YES/NO/UNKNOWN`.
   - The raw text generated by the model.

The backend has permissive CORS enabled (`allow_origins=["*"]`), so it can accept requests from `file://` origins.

### Option 2: serve the frontend via a simple HTTP server

If you prefer to serve the HTML from `http://localhost`, you can run a simple static server in the
`frontend/` directory:

```bash
cd frontend
python -m http.server 8001
```

Then open:

- `http://127.0.0.1:8001/` in your browser.

The JavaScript in `index.html` still calls the backend on `http://127.0.0.1:8000/predict`.

## How the pieces line up with the training notebook

- The 10 questions (A1–A10) in the form are the same as the `questions` list defined in
  `llm_train.ipynb` (Part 4: "PREPARING TRAINING DATA").
- The backend builds the prompt exactly like the `create_prompt(row)` function in that notebook:
  - `Patient screening info:` header.
  - 10 question/answer lines (e.g. `Does your child look at you when you call his/her name? Answer: 1`).
  - A demographics line: `Age`, `Sex`, `Jaundice`, `Family history of ASD`.
  - Final question: `Does this child have autism risk? Answer YES or NO.`
- The full input to the model is:

  ```text
  ### Instruction:
  <prompt as above>

  ### Response:
  ```

  This matches how `df_combined['text']` was constructed during training in the notebook.
- The model output is post-processed by searching for `YES` or `NO` (case-insensitive), and anything
  else is treated as `UNKNOWN`.

## Troubleshooting

- **Model fails to load / CUDA / bitsandbytes issues**
  - Ensure you can still run the fine-tuning or evaluation cells from `llm_train.ipynb` in the same
    virtual environment. The backend uses the same stack (4-bit quantization, `bitsandbytes`, etc.).
- **Very slow first request**
  - Loading a 7B model with LoRA and quantization can take time. The first `uvicorn` startup and
    first `/predict` call will be the slowest.
- **CORS / browser errors**
  - The backend enables CORS for all origins. If you changed the `API_URL` in `frontend/index.html`,
    ensure it still points to the correct backend URL and that the backend is running.

## Summary of files added for the web app

- `backend/main.py`
  - FastAPI app exposing `/predict` and `/health`.
  - Loads `mistralai/Mistral-7B-Instruct-v0.1` and attaches `autism_screening_mistral_final` LoRA.
  - Reuses the exact prompt format from `llm_train.ipynb`.

- `frontend/index.html`
  - Static page with the 10 questions (A1–A10) and demographic fields.
  - Sends a JSON payload to the backend and displays the prediction and raw model text.
